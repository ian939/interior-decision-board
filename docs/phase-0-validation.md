# 0단계 기술 검증 결과

- 검증일: 2026-10-06 (Asia/Seoul)
- 상태: **조건부 통과**
- 범위: 로컬 Claude CLI, URL 메타데이터, 외부 HTTPS/CORS/로그인, 텔레그램 준비 상태, 로컬 개발 환경

## 결론

계획한 구조는 구현 가능하다.

- 로컬 Claude CLI는 비대화식·제한 모드에서 구조화 JSON을 안정적으로 반환했다.
- 로컬 Node 서버를 임시 Cloudflare HTTPS 터널로 노출하고, GitHub Pages 예상 Origin에 대해 CORS·로그인·인증 API 왕복을 성공했다.
- YouTube와 네이버 블로그는 API 키 없이 제목, 설명, 썸네일을 확보했다.
- Instagram/Reels는 공개 HTML에 유효한 설명과 썸네일이 없어 자동 정리 품질을 보장할 수 없다. 실패를 제품의 정상 상태로 다뤄야 한다.
- 텔레그램 Bot API 실검증은 봇 토큰이 없어 보류했다.
- GitHub Pages 실제 배포와 고정 HTTPS 주소는 저장소 및 운영 도메인이 정해진 뒤 검증해야 한다.

## 검증 결과

### 1. Claude CLI 구조화 출력

결과: **통과**

- 비대화식 `--print` 실행
- JSON Schema 기반 구조화 출력
- `--restricted`, `--safe-mode`, 도구 목록 비활성화
- 권한 요청 비활성화 및 세션 미보존
- 실행 시간: 약 6.3초
- 결과 필드: 출처 유형, 요약, 주제 태그
- 금지한 공간 필드는 출력되지 않음
- 웹 검색·웹 가져오기 사용 횟수 0

운영 판단:

- 카드 생성은 요청-응답 안에서 기다리지 않고 영속 작업 큐로 처리한다.
- 작업 제한 시간은 초기 60초, 재시도는 최대 2회로 시작한다.
- JSON Schema 검증 실패 시 원문 카드는 유지하고 수동 입력 상태로 전환한다.

### 2. URL 메타데이터와 썸네일

결과: **부분 통과**

| 소스 | HTTP | 제목 | 설명 | 썸네일 | 판단 |
| --- | ---: | --- | --- | --- | --- |
| YouTube 공개 영상 | 200 | 확보 | 확보 | 확보 | MVP 사용 가능 |
| Instagram 공개 Reel | 200 | `Instagram` 일반 제목만 확보 | 실패 | 실패 | 제한 상태 필요 |
| 네이버 블로그 인테리어 글 | 200 | 확보 | 확보 | 확보 | MVP 사용 가능 |

추가 확인:

- YouTube HTML 약 1.35MB, Instagram 약 0.65MB, 네이버 블로그 약 0.36MB를 읽었다.
- 수집기는 본문 최대 2MB, 리다이렉트 최대 5회, 요청 제한 시간 15초로 검증했다.
- `127.0.0.1` URL 요청은 즉시 `private_ipv4`로 차단되어 SSRF 기본 방어가 동작했다.

운영 판단:

- YouTube/블로그는 제목·설명·썸네일을 기반으로 Claude 요약을 생성한다.
- Reels는 자동 수집이 실패하면 출처 아이콘, 원문 링크, 사용자 메모만 표시한다.
- Reels 사용자는 텔레그램 또는 웹에서 대표 이미지를 추가 파일로 첨부할 수 있게 한다.
- Instagram 로그인 우회나 비공식 세션 스크래핑은 MVP에 넣지 않는다.
- YouTube 자막 기반 요약은 `yt-dlp` 설치 후 별도 검증한다. 자막 실패 시 메타데이터 요약으로 자동 전환한다.

### 3. 외부 HTTPS, CORS, 로그인

결과: **통과(임시 주소)**

로컬의 검증 서버를 Cloudflare Quick Tunnel에 연결해 외부 HTTPS 주소에서 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| `/health` 외부 HTTPS 호출 | 200 |
| GitHub Pages 예상 Origin CORS 헤더 | 정상 |
| CORS preflight | 204 |
| 비밀번호 로그인 | 성공 |
| 로그인 토큰으로 보호된 `/cards` 호출 | 200 |
| 허용하지 않은 Origin 로그인 | 403 |

검증 후 임시 터널과 로컬 서버는 정상 종료했으며 포트도 닫힌 것을 확인했다.

운영 판단:

- GitHub Pages 정적 프런트와 로컬 API의 분리 구조는 기술적으로 가능하다.
- Quick Tunnel 주소는 매번 바뀌며 가용성 보장이 없으므로 운영에 사용할 수 없다.
- 운영 전 고정 HTTPS 주소를 제공하는 Named Tunnel 또는 동등한 방식을 확정해야 한다.

### 4. 텔레그램

결과: **보류**

- 검증 스크립트와 토큰 비노출 실행 절차를 준비했다.
- 현재 세션에 `TELEGRAM_BOT_TOKEN`이 없어 `getMe` 실호출은 실행하지 않았다.
- 토큰은 채팅, 소스 파일, 명령 기록에 넣지 않고 로컬 환경 변수로만 주입해야 한다.

### 5. GitHub Pages

결과: **부분 통과**

- GitHub CLI 로그인과 저장소/워크플로 권한을 확인했다.
- GitHub Pages에서 사용할 예상 Origin을 기준으로 백엔드 CORS 동작을 검증했다.
- 아직 프로젝트 저장소가 없으므로 실제 Pages 배포와 모바일 브라우저 검증은 수행하지 않았다.

## 재현 도구

검증 코드는 [`spikes/phase0`](../spikes/phase0/README.md)에 있다.

- `verify-claude.mjs`: 제한된 Claude CLI 구조화 출력
- `verify-sources.mjs`: 안전한 URL 수집과 메타데이터 추출
- `verify-telegram.mjs`: 토큰이 있을 때 봇 연결 확인
- `probe-server.mjs`: HTTPS 터널, CORS, 로그인과 인증 호출 확인

모든 `.mjs` 파일은 `node --check`를 통과했다.

## 0단계 완료를 위해 남은 작업

1. BotFather로 만든 텔레그램 봇 토큰을 로컬 환경 변수에 넣고 봇 연결을 검증한다.
2. 운영용 고정 HTTPS 주소 방식을 정하고 재부팅 후 자동 연결을 검증한다.
3. GitHub 저장소 이름을 정해 최소 Pages 화면을 실제 배포한다.
4. 사용자가 실제로 보관하려는 YouTube, Reels, 블로그 링크 각 1개로 수집 품질을 재확인한다.
5. YouTube 자막이 필요한 경우 `yt-dlp`를 설치하고 한국어/자동 생성 자막 성공 및 실패 흐름을 검증한다.

## 구현 진입 조건

텔레그램 토큰과 고정 주소는 1단계 기본 보드 구현을 막지 않는다. 따라서 기본 보드 구현은 시작할 수 있다. 다만 외부 실사용 출시 전에는 위의 1~3번을 반드시 완료해야 한다.
